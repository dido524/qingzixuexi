# 晴子学习助手第一版设计说明

## 1. 目标

在 Windows 桌面提供一个“一键拍照、连续翻页、自动分析”的学习资料入口。家长或孩子将作业、练习或试卷放在证件拍照机下，通过同一个界面完成整份资料的采集。程序自动识别语文、数学或英语，判断资料是否已经由老师批改，完成相应分析，并把原始材料、分析结果、错题与知识点更新到 `C:\晴子知识库\5th grade`。

第一版服务于一个学生、五年级和三个科目。它不承担班级管理、多人账号、手机同步或在线分享。

## 2. 已确认的约束

- 拍照设备：Windows 中显示为 `USB Camera`，硬件 ID 为 `VID_BC15&PID_2C1B`，当前状态正常。
- 电脑上同时存在 `Logi C270 HD WebCam`，程序必须优先选择证件拍照机，不能误用罗技摄像头。
- 知识库根目录：`C:\晴子知识库\5th grade`。
- 已有科目目录：`语文`、`数学`、`英语`。
- 一次任务可以连续拍摄多页；每页都可重拍。
- 资料可能已经由老师批改，也可能完全没有批改。
- 原始文件和知识库保存在本机；分析可使用云端模型。
- 第一版生成 Obsidian 可读取的 Markdown，但不依赖 Obsidian 或 LLMWiki 才能运行。
- 电脑当前未安装 Obsidian 或 LLMWiki。
- 第一版使用当前已登录 ChatGPT 的 Codex CLI 作为分析引擎，不在代码、配置或日志中保存 API Key。

## 3. 用户操作流程

1. 用户双击桌面上的“晴子学习助手”。
2. 程序连接证件拍照机并显示实时预览。
3. 用户点击“拍摄本页”。
4. 拍摄后显示静态预览，用户选择“重拍”或“下一页”。
5. 用户换页后继续拍摄；页码始终可见。
6. 整份资料拍完后，用户点击“完成并分析”。
7. 程序先把全部原始图片安全写入本机，再开始任何模型调用。
8. 程序分析整份资料，判断科目、批改状态、题目、答案、正误、错因和知识点。
9. 科目置信度足够时自动归档；置信度不足时只要求用户在“语文、数学、英语”中选择一次。
10. 分析完成后，界面显示本次摘要、保存位置和“查看详情”按钮。

关闭窗口、网络断开或分析失败均不得删除已经拍摄的原始图片。

## 4. 界面范围

第一版使用单窗口桌面界面，包含：

- 摄像头状态和实时取景区域；
- 当前页码；
- “拍摄本页”“重拍”“下一页”“完成并分析”四个主操作；
- 处理进度和错误提示；
- 科目纠正选择器，仅在自动判断不确定时出现；
- 分析摘要，包括题目数、错题数、主要薄弱知识点和待确认项目；
- “打开本次资料文件夹”和“查看详细分析”入口。

界面不暴露模型、提示词、JSON、数据库或其他技术概念。

## 5. 数据目录

所有用户资料位于三个已有科目目录内。每个科目使用相同结构：

```text
C:\晴子知识库\5th grade\数学\
├─ 原始资料\
│  └─ 2026\09\2026-09-15_数学_试卷_001\
│     ├─ page_001.jpg
│     ├─ page_002.jpg
│     └─ document.json
├─ 分析记录\
│  └─ 2026\09\2026-09-15_数学_试卷_001.md
├─ 错题\
│  └─ 错题索引.md
├─ 知识点\
│  └─ 分数除法.md
└─ 待处理\
   └─ 2026-09-15_175900_001\
```

语文和英语采用同样结构。程序自己的配置、日志和 SQLite 数据库存放在项目运行目录或 Windows 用户应用数据目录，不混入孩子的资料目录。

## 6. 数据所有权和真相来源

系统分为三层：

1. **原始资料层**：拍摄得到的 JPG，是不可覆盖的证据。重拍产生新文件，确认采用新图后才把旧图标为废弃；不静默覆盖。
2. **结构化记录层**：SQLite 与 `document.json` 保存题目、学生答案、老师标记、判断结果、知识点、置信度及来源页码。长期统计以这一层为准。
3. **阅读层**：程序从结构化记录生成 Markdown，供文件浏览器或 Obsidian 阅读。Markdown 可以重新生成，不作为唯一事实来源。

每个分析结论必须能够追溯到文档、页码和题号。

## 7. 自适应判卷

分析引擎先判断整份资料属于以下哪种模式：

- **老师已批改**：检测红笔、勾叉、圈画、扣分、分数或评语。老师的明确判定优先，模型负责提取和解释错因。
- **尚未批改**：模型识别题目与学生答案，自行给出答案、判定和说明。
- **混合模式**：一部分题有老师批改，另一部分没有，逐题选择处理方式。

主观题、作文、字迹不清、题目缺页、答案被遮挡或模型结论冲突时，状态设为“待确认”。待确认项目不直接改变长期掌握度。

## 8. 分析输出结构

每份资料至少生成以下字段：

- 科目、资料类型、拍摄时间、页数；
- 是否存在老师批改及其证据；
- 题号、题型、题干摘要、学生答案、参考答案；
- 正确、错误、部分正确或待确认；
- 错因类别：知识概念、审题、计算、步骤、表达、书写或粗心；
- 关联知识点；
- 分析置信度和来源页码；
- 本次总结与建议复习项。

第一版只记录有证据支持的结论。模型不能识别的内容保留原图引用和“待确认”，不得编造清晰答案。

## 9. 长期知识库更新规则

每个知识点记录：

- 首次出现和最近出现日期；
- 总练习次数、正确次数、错误次数；
- 老师判定和系统判定分别统计；
- 常见错因；
- 关联错题；
- 最近趋势；
- 是否需要复习；
- 复习后重新检验的结果。

同一份文档重复分析时必须幂等：更新原记录，而不是把题目和统计重复累加。待确认内容只有在确认后才计入掌握度。

第一版先建立数据和 Markdown 页面，不包含复杂的自动出卷编辑器。后续版本可依据这些结构化记录生成专项复习材料和检验卷。

## 10. 知识库呈现和使用方式

程序在知识库根目录生成一个可离线打开的 `知识库首页.html`。用户可以从桌面程序的“打开知识库总览”按钮进入，也可以直接双击该文件。首页采用已经确认的布局：

- 左侧导航：学习总览、语文、数学、英语、错题本、知识点地图、待家长确认、历次作业与试卷；
- 顶部摘要：本月收录资料数、已分析题目数、重点短板数和待确认数；
- 三科概况：展示近期掌握趋势，不用单次分数替代长期表现；
- 薄弱知识点：依据错误频率、最近表现和复测结果排序；
- 最近更新：每项均可返回原始图片、页码和题号；
- 使用入口：查看错题、生成考前复习包、发起掌握度检验。

第一版启用总览、三科页面、错题、知识点、待确认和原始资料追溯。考前复习包与掌握度检验保留入口和数据接口，在后续版本启用；第一版不得显示成已经可用的功能。

首页是程序根据 SQLite 数据生成的只读、自包含 HTML 快照，不需要启动服务器，也不依赖 Obsidian。深入阅读时，用户可以选择用 Obsidian 打开 `C:\晴子知识库\5th grade`，查看 Markdown 页面之间的链接。HTML、Markdown 或 Obsidian 均不能直接改写结构化成绩记录；确认和纠错必须通过桌面程序完成。

## 11. 分析引擎和隐私

第一版通过本机已登录的 Codex CLI 提交本次拍摄的图片，并要求模型按照固定 JSON Schema 返回结果。调用过程：

- 只提交本次任务图片和必要的年级、科目上下文；
- 不提交整个历史知识库；
- 不在提示词、日志或配置中写入孩子不必要的个人信息；
- Codex 以只读工作模式执行，不允许模型直接修改知识库文件；
- 程序先校验模型返回的 JSON，再由本地代码执行写入；
- 调用会占用当前 ChatGPT/Codex 账号的使用额度；
- 无网络、未登录或额度不足时，资料进入对应科目的“待处理”，以后可重新分析。

## 12. 组件边界

- `camera`：枚举摄像头、选择证件拍照机、实时预览和抓图。
- `capture_session`：维护页序、重拍、完成和原图落盘。
- `analyzer`：构造只读分析请求、调用 Codex、接收结构化结果。
- `schema`：校验分析结果，拒绝缺字段或非法状态。
- `classifier`：根据分析结果和置信度决定科目或请求人工选择。
- `repository`：管理 SQLite、JSON、图片和幂等更新。
- `markdown_exporter`：生成 Obsidian 兼容的分析、错题和知识点页面。
- `dashboard_exporter`：生成已经确认的本地知识库总览 HTML，并提供原题追溯链接。
- `ui`：只负责显示状态与接收用户操作，不直接处理数据库或模型逻辑。

这些模块通过明确的数据对象通信，便于后续替换摄像头接口或模型，而不改变知识库格式。

## 13. 错误处理

- 找不到证件拍照机：显示明确提示，不自动切换到罗技摄像头。
- 摄像头被其他应用占用：提示关闭占用程序并重试。
- 图片模糊、过暗、裁切不全：拍摄后立即提示重拍，不进入分析。
- 写入失败：保留当前会话临时文件并显示恢复位置。
- 科目判断不确定：要求用户选择，不猜测归档。
- 模型响应无效：保留原图和原始响应诊断信息，但不更新知识点统计。
- 分析中断：下次启动时显示可恢复任务。
- 同一任务重复提交：按文档 ID 更新，不重复计数。

## 14. 技术选择

- Python 3.13 作为实现语言；
- Tkinter 提供轻量单窗口界面；
- OpenCV 或等价 Windows 摄像头接口完成预览和高分辨率抓图；
- Pillow 负责图片方向、压缩和质量检查；
- SQLite 保存长期结构化数据；
- Markdown 和 YAML front matter 提供 Obsidian 兼容阅读层；
- 自包含 HTML 提供无需安装软件的知识库全貌和导航入口；
- Codex CLI 接收多页图片并返回受 JSON Schema 约束的分析结果；
- PyInstaller 打包为 Windows 可执行程序；
- 桌面放置“晴子学习助手”快捷方式。

如果 Python 3.13 与某个摄像头依赖不兼容，构建环境可以使用项目私有的稳定 Python 版本；不会替换或破坏电脑现有 Python。

## 15. 第一版不包含

- Obsidian 自动安装或插件配置；
- LLMWiki；
- 手机端、云同步和多人账号；
- 与学校系统连接；
- 自动打印；
- 无人工复核的作文评分；
- 基于全量历史数据的自动组卷。

这些项目不会阻碍后续扩展，但不进入第一版验收范围。

## 16. 验收标准

第一版完成需同时满足：

1. 桌面快捷方式可启动程序。
2. 程序稳定选择 `VID_BC15&PID_2C1B` 证件拍照机，不误选 Logi C270。
3. 能连续拍摄至少 10 页，支持任意页重拍，并保持正确页序。
4. 点击“完成并分析”前，原始图片已经安全保存。
5. 语文、数学、英语样例均能归档到正确的已有科目目录；不确定时出现人工选择。
6. 已批改、未批改和混合批改三种样例都能产生符合 Schema 的结果。
7. 至少生成本次分析 Markdown、错题索引更新和知识点页面更新。
8. 能生成并离线打开已确认布局的 `知识库首页.html`，从总览追溯到科目、知识点、错题和原始资料。
9. 尚未实现的复习包和掌握度检验入口必须明确标为后续功能，不能造成已可用的误解。
10. 模型失败、网络中断或程序重启不会丢失原图。
11. 重复分析同一任务不会重复累计知识点统计。
12. 日志不包含密钥或不必要的孩子个人信息。
13. 在实际证件拍照机上完成一次多页端到端验证，并人工核对保存路径与分析内容。
