# 晴子学习助手：混合学科按页拆分设计

日期：2026-09-16
状态：已与用户确认，待实施规划

## 1. 背景与目标

当前一次拍摄批次只能保存一个顶层学科。若同一批次中包含数学页和英语页，模型只能给出一个候选学科；低于置信度阈值时，程序要求用户为整批选择一个学科。这样会把另一学科的题目、错题和知识点一并写入错误的知识库。

本改动的目标是：

- 模型一次分析整批资料，同时为每一页给出学科判断。
- 学科明确的页面自动按语文、数学、英语拆分成独立文档。
- 单页混合学科或低置信度时暂停，让用户确认该页学科。
- 所有待确认页面完成后，才一次性归档、写入知识事实并发布首页。
- 确认窗口以大图为主；程序不在前台时，Windows 任务栏图标闪烁提醒。
- 保持单学科流程、旧缓存任务、恢复任务和家长复核流程兼容。

非目标：

- 不自动修复已经入库的历史混合批次。
- 不按一道题拆分学科；最终归类单位是整页。
- 不为每一页单独调用一次大模型。

## 2. 分析结果契约

分析响应新增 `page_subjects`，每个已拍页面必须且只能出现一次：

```json
{
  "page": 5,
  "suggested_subject": "英语",
  "confidence": 0.98,
  "needs_confirmation": false,
  "reason": "页面为英语语法和词汇练习"
}
```

规则：

- `page` 必须对应当前捕获文档中的真实页码，不得重复或遗漏。
- `suggested_subject` 只能是语文、数学、英语。
- `confidence` 必须在 0 到 1 之间。
- 模型发现单页本身含多个学科、页面内容不足或置信度低于配置阈值时，必须设置 `needs_confirmation=true`。
- 程序再次执行独立校验：即使模型漏标，只要置信度低于阈值，也强制人工确认。
- 每道题继续引用原始 `page`；拆分时由页面最终学科决定题目归属。
- 顶层 `subject` 和 `subject_confidence` 暂时保留，用于兼容旧缓存和单学科分析；新流程不再用它决定混合批次的最终归档。

领域层新增不可变的 `PageSubjectAssignment`。`AnalysisResult` 增加页面学科集合，解析器及 JSON Schema 执行严格字段校验。旧缓存中没有 `page_subjects` 时走原有整批学科确认流程，不重新调用模型。

## 3. 拆分决策与标识

程序先形成一个持久化的页面分配表：

1. 明确页面直接采用模型判断。
2. 模糊或单页混合页面进入待确认集合。
3. 用户每确认一页，选择结果立即写入权威任务负载。
4. 仍有未确认页面时，不创建部分学科文档，不更新知识统计。
5. 全部页面都有最终学科后，生成确定性的拆分计划。

文档标识：

- 全批只有一个学科时，保留原始 `capture-...` 文档编号。
- 混合批次按学科生成稳定子文档编号：`<批次编号>--chinese`、`<批次编号>--math`、`<批次编号>--english`。
- 子文档记录共同的父批次编号，便于追溯和恢复。
- 重试始终复用相同编号，不产生重复文档或重复知识统计。

每张原图只能分配给一个最终学科。子文档保留原始页码及文件名，例如英语子文档可以包含 `page_005.jpg`、`page_006.jpg`，从而维持模型题目、原图和家长复核之间的稳定引用。

## 4. 持久化与发布

原始拍摄目录在整个拆分完成前保持为权威来源。拆分过程按以下顺序执行：

1. 校验所有源图片路径、页码和 SHA-256。
2. 为每个学科建立受路径守卫保护的暂存目录，仅复制分配给该学科的页面。
3. 写入包含父批次、最终页面分配和源哈希的拆分清单。
4. 在一个数据库事务内写入所有子文档、页面、问题、知识点关联和对应的工作流记录。
5. 重新计算受影响学科的知识统计。
6. 通过现有发布协调器一次性生成所有学科 Markdown、错题索引和知识库首页。
7. 文件发布成功后标记父批次及子任务完成；最后才允许清理原始暂存资产。

任一步骤失败时：

- 已保存的页面分配和人工选择不得丢失。
- 任务进入可重试状态。
- 数据库事务回滚或发布 outbox 保证不会只更新一部分知识事实。
- 重试验证已有文件哈希并复用同一拆分计划，确保幂等。

每个子文档具有自己的工作流记录，因而待家长复核、复核审计和重新发布仍以子文档为单位工作。父批次只负责编排、展示总体状态和关联子文档，不参与知识点累计。

## 5. 待确认界面

新增页面学科确认窗口：

- 默认占屏幕可用区域约 85%，但不超过实际工作区。
- 图片区域随窗口伸缩并占主要空间，保持原图比例，使用高质量缩放。
- 顶部显示“第 N/M 张待确认页面”、模型建议、置信度和判断依据。
- 语文、数学、英语按钮固定在窗口底部；最大化、恢复或大图加载后均保持可见。
- 用户选择后立即保存，自动显示下一张待确认页面。
- 最后一页确认后关闭窗口并继续拆分，无需再次点击“完成并分析”。
- 用户关闭确认窗口只表示稍后处理，任务保持待确认，不丢失分析结果。

旧式整批学科确认仍用于没有 `page_subjects` 的历史缓存任务。

## 6. Windows 任务栏提醒

将 Windows 提醒封装成独立、可注入的通知器：

- 新任务进入页面学科待确认状态且主窗口不在前台时，使用 `FlashWindowEx` 闪烁主窗口的任务栏图标。
- 用户激活主窗口或确认窗口后立即停止闪烁。
- 主窗口已经处于前台时不闪烁。
- 同一待确认状态只触发一次，不在每次 UI 轮询时重复调用。
- 非 Windows 环境使用无操作实现，保证测试和代码可移植。
- 闪烁只是提示，不改变窗口焦点、不强制抢占用户输入。

## 7. 恢复与兼容

- 权威状态仍保存在 SQLite 工作流任务中；`analysis_state.json` 是可修复镜像。
- 任务负载保存模型页面判断、人工覆盖、拆分计划、子文档编号及发布状态。
- 重启后，程序恢复待确认任务并重新打开尚未确认的第一页；不会重新调用模型。
- 旧单学科分析响应按原逻辑处理。
- 旧的 `needs_subject_confirmation` 任务继续显示整批学科选择，不强行转换。
- 已经入库的历史混合批次不自动迁移；需要单独、显式的纠正流程。

## 8. 数据与安全约束

- 不信任模型返回的页码、学科、路径或文档标识；全部在领域边界重新验证。
- 不允许页面遗漏、重复分配、越界页码、未知学科或空拆分组。
- 所有文件操作继续使用现有固定根目录、重解析点检查、哈希校验和原子替换。
- 人工确认是最终权威值，并记录确认来源；模型建议保留作审计信息。
- 子文档只包含本学科页面上的题目，禁止跨学科知识点进入统计。

## 9. 测试与验收

采用测试驱动实现，至少覆盖：

- Schema 接受完整页面映射，拒绝遗漏、重复、越界和非法学科。
- 单学科批次保持原文档编号且不显示确认窗口。
- 数学与英语页面均高置信度时自动生成两个子文档。
- 单页混合或低置信度时整批暂停，明确页面不提前入库。
- 大图确认窗口在 1024×700、推荐尺寸以及最大化后恢复时按钮始终可见。
- 每次选择即时持久化；关闭并重启后从剩余页面继续。
- 前台窗口不闪烁；后台进入待确认时闪烁；获得焦点后停止。
- 数据库写入或文件发布失败后可幂等重试，无重复文档和重复知识累计。
- 子文档的错题、知识点、原图、分析记录和复核入口相互隔离。
- 旧缓存任务、旧整批确认和现有单学科端到端流程全部回归通过。

验收示例：一个 6 页批次中第 1—4 页为数学、第 5—6 页为英语，且所有页面学科明确。程序应不要求整批选学科，自动生成一个 4 页数学文档和一个 2 页英语文档；数学知识库不得出现英语知识点，英语知识库不得出现数学题目。
