# OCR 批改与确认入库设计

## 目标

同一拍摄会话可包含多张同学科作业图片。对老师未批改的页面，视觉模型完成 OCR、判题并返回每题答案区域的归一化坐标；应用在本机生成不覆盖原图的批改副本。模型判断为错误或部分正确的题先进入“待家长确认”，确认后才计入知识统计和错题库。

## 交互

- 复用“拍下这一页”“下一页”“完成并分析”。
- 复用“本次分析”：有批改结果时打开多页批改结果页，否则打开原分析详情。
- 复用“待家长确认”：显示批改图并预选模型建议，家长保存后发布到知识库。
- 复用“资料文件夹”：保留原图、批改图和批改结果页。

## 数据契约

每题新增 `answer_bbox={x,y,width,height}`，取值为相对原图宽高的 0..1 数值。宽高必须大于零，且矩形不能越出页面。传输 Schema 强制模型返回；领域 Schema 允许旧缓存缺省，保证历史任务可恢复。

模型原始 `status` 保留。有效事实视图把 `decision_source=model` 且原始状态为 `incorrect/partial`、同时尚无家长复核的题映射为 `needs_review`。老师批改结果不受此门控。家长确认以现有审计表和发布事务覆盖有效事实。

## 批改图

本机 Pillow 渲染器按页输出 `批改结果_第NNN页.png`，并生成可打印的 `批改结果.html`。原图在渲染前后校验哈希，不被改写。颜色和符号区分正确、错误、部分正确、待确认；模型错误注明“模型建议，待家长确认”。所有路径只从已验证归档清单推导。

## 多页与混合学科

同学科多页作为一个文档生成一组批改图和一个结果页。既有混合学科拆分仍按页生成子文档；每个子文档独立渲染，父任务汇总子结果路径。

## 失败与恢复

批改图路径写入工作流 payload。渲染可重复执行且输出确定；崩溃恢复时从归档原图和结构化分析重新生成。渲染失败不覆盖原图，并让任务保持可重试状态。
