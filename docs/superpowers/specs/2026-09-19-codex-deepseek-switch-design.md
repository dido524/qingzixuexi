# Codex / DeepSeek 模型切换设计

## 目标

晴子学习助手提供且仅提供“原生 Codex”和“DeepSeek”两种运行时模型选择。默认继续使用已经登录 ChatGPT 账号的 Codex CLI；用户可在应用内填写 DeepSeek API 地址、模型名和 API 密钥，并让随后发起的作业分析、学情报告、模拟卷生成与模拟卷校验统一使用 DeepSeek。

## 边界

- 不建立通用多供应商插件系统。
- 不修改知识库数据库结构、确认规则、归档规则或打印格式。
- 不将 API 密钥写入普通 JSON、SQLite、知识库、日志、异常消息或 Git。
- 不在没有用户主动填写密钥时调用 DeepSeek。
- 不自动把失败的 DeepSeek 请求静默改交 Codex；失败必须保留资料并明确提示，避免未知费用和模型来源。

## 组件

### 本地模型设置

`ModelSettingsManager` 在应用数据目录保存非敏感 JSON：当前提供方、DeepSeek HTTPS API 地址和模型名。DeepSeek API 密钥使用 Windows DPAPI 按当前 Windows 用户加密后单独保存。设置管理器提供线程安全快照；UI 与后台工作线程共享同一实例。

### DeepSeek 请求适配

`DeepSeekClient` 使用 Python 标准库 HTTPS 调用 OpenAI 兼容的 `/chat/completions`。本地图片以内联 base64 data URL 发送；响应使用 JSON Output，并继续交给现有 JSON Schema、领域对象和事实校验。网络、认证、限流、超时和无效响应只转换成应用自有错误码，不显示远端响应正文或密钥。

### 任务路由

四个小型路由器分别实现现有接口：作业分析、报告文字、模拟卷生成、模拟卷校验。每次新任务开始时读取设置快照并选择 Codex 或 DeepSeek。现有 Codex 类保持不变，DeepSeek 类复用同一提示词与同一本地校验规则。

### 用户界面

主窗口标题区显示当前模型，并提供“模型设置”。设置窗口包含两项选择、API 地址、模型名、密码输入框、已保存状态和清除密钥选项。空白密钥表示保留已保存密钥；DeepSeek 配置缺少密钥时禁止保存为当前模型。后台忙碌时禁止更改设置。

## 错误与恢复

- DeepSeek 缺少密钥：提示进入模型设置，不发出网络请求。
- 401/403：提示密钥无效或无权限。
- 429：提示额度或限流。
- 网络/超时/服务端错误：资料保持待处理，可重试。
- JSON 或业务 Schema 无效：沿用现有 `invalid_response` 安全失败。
- 学情报告仍保留本地模板回退；作业分析和模拟卷不静默换模型。

## 验证

使用假 HTTP 传输测试真实请求体、图片 data URL、认证头、JSON解析和错误净化；使用真实设置存储测试持久化但不记录明文密钥；使用 Tk 测试验证选择与设置交互；最后运行完整测试、打包、安装和安全启动检查。没有用户 API 密钥时不进行真实 DeepSeek 计费调用。
